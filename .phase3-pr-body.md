## Summary

Implements an isolated, disabled-by-default Hootsuite provider on top of Phase 2:

- Hootsuite OAuth authorization-code and refresh lifecycle with signed, replay-rejected state
- root-mounted mode-0600 token storage and secret-file configuration
- social profile discovery and canonical network/status normalization
- message create/schedule, delete/cancel, lookup reconciliation, and media upload initialization
- normalized authentication, rate-limit, unavailable, rejection, and unknown-result handling
- deterministic explicit-account canary routing for new posts only
- immutable historical ownership, no dual publishing, and no automatic provider failover
- provider capability, migration, polling-event, acceptance, and rollback documentation

## Safety and blockers

All source defaults remain off. No production deployment, Hootsuite activation, provider publish, Odoo write, dual publishing, automatic failover, account mutation, or credential change occurred.

Phase 2 Postly authentication is not certified. No approved Hootsuite developer app, OAuth credential, or staging-safe account was found. Real OAuth, account discovery, media transfer, schedule/cancel, and migration canary therefore remain blocked and this PR must not be merged or deployed as a certified canary.
